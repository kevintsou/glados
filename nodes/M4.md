# M4 實作

## 介面（框架固定）

- **目的**：依 spec、驗收合約與 case 規劃並修改 code，產出可以 build、會通過測試的 commit。v0.9 起原本 M3 的實作計畫併進這一站。
- **層級**：模組
- **由誰做**：規劃與實作是外部互動，由人開 agent 照實作 skill 完成；正式 build 是工具步驟，由串接層在提交後執行（[framework/04 §4.2](../framework/04_rules.md#42-兩種執行方式)）。
- **從哪裡進來**：
  - M2 完成。
  - P2 改版（介面或記憶體預算變了）。
  - M5 必要 case FAIL、M6 審查有阻擋項目（計入 M4 的輪數）。
  - 人指定重做。
- **輸入**：模組 spec 與驗收合約（有 H 核准）、測試實作與測試基準（唯讀）、架構文件（介面與記憶體預算）。
- **輸出**：
  - 模組 commit（在模組工作 branch）；commit message 寫模組名稱與對應的 CR。
  - 實作計畫（`artifacts/modules/<模組>/plan.md`，選用）：要改的檔案、每一步對應哪些 case、預估的記憶體影響；給 M6 與之後的重做參考。
  - build 證據：由串接層執行的正式 build 產出的 image hash（每個必要 build 設定一個）、記憶體用量。正式 build 每次都 clean build 全部必要設定，包括 bootcode 與 burner，就算只改到其中一邊（[framework/09 §9.4](../framework/09_build_configurations.md#94-sandaruburner-是專案的一部分)）。**放行看的是串接層執行的那次 build，不是 agent 在 session 裡自己 build 的結果。**
- **擋關檢查**：只寫在允許範圍內、測試沒被動過、build 零警告、記憶體在預算內。
- **出口關卡**：無。
- **失敗時**：build 失敗、有 warning、超出預算 → 實作 skill 在同一次執行裡重做；提交後的正式 build 沒過也回到 M4。和 M5、M6 退回的合計最多 3 輪：上限由 skill 遵守，累計由串接層寫進工作包，超過只提示；需要大範圍改動模組 code 範圍以外的檔案、牽涉需求或介面 → 交給人。
- **可寫範圍**：差異分析列出的這個模組的 code 範圍，以及 `artifacts/modules/<模組>/plan.md`；禁止改測試實作與驗收合約，不能改生成區。

人工也可以直接 commit，接回流程時照樣經過上面的擋關檢查與 M5、M6（[framework/04 §4.7](../framework/04_rules.md#47-新-commit-與人工修改)）。

## 實作（待展開）

- **執行者**：人開的 agent 照實作 skill 規劃與實作（建議用強模型）；session 中自己 build、修的循環可以用 ds5-build／andes-build；重開時靠 `plan.md` 與交接說明接續。正式 build 由串接層執行（共用待辦 BC-010 的 DS-5 包裝）。
- **工具**：ds5-build／andes-build。
- **待展開議題**：
  - [playbook 審查意見](../notes/playbook_kit_review.md)建議的 bootcode 通用紅線（linker script 不准動、所有 polling 都要有 timeout 等），要不要列進可寫範圍的禁止項目或必要規則。
