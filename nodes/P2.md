# P2 差異分析

## 介面（框架固定）

- **目的**：把 G0 核准的範圍清單對到 code 位置，再切成模組。範圍本身（做不做、留不留）在 P0 已經決定，P2 不重新討論。
- **層級**：專案
- **從哪裡進來**：
  - P1 完成之後。
  - C 變更處理判定「全新功能，不碰既有模組」→ 在 P2 追加模組。
- **輸入**：
  - 範圍清單（有 G0 核准）。
  - 來源快照（G0 核准的版本；不直接讀 Jira／Confluence）。
  - 基線報告。
  - 專案設定的 code 模組對照、共用層規則、衝突熱點。
- **輸出**：差異分析（`artifacts/delta.md`），至少包括：
  - 範圍清單裡標成新增、修改、移除的每一項一列：對到哪些 code、屬於哪個模組。
  - 每個模組的 code 範圍。
  - 受影響的既有功能（regression 範圍）。
  - 模組之間的相依與執行順序；改到衝突熱點檔案的模組標為序列。
- **出口檢查**：範圍清單都有歸屬、模組順序已定、regression 範圍已定。
- **出口關卡**：G1 範圍核准。
- **失敗退回**：
  - 範圍清單或專案設定要改（例如某一項在 code 上做不到） → 退回 P0，重開 G0（只審差異）。
  - CR 內容不清楚 → 登記待確認事項，節點轉為「等待外部回覆」。CR 負責人在 Jira 補寫後，由外部來源同步發現並交給 C（[framework/04 §4.7](../framework/04_rules.md#47-s-版本同步)）；GC 接受後，P2 用新版來源快照接續。
- **迴圈上限**：待定。
- **可寫範圍**：可寫 `artifacts/delta.md`；禁止改 FW source。
- **人怎麼參與**：只在關卡。
- **獨立性要求**：無。
