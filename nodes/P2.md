# P2 差異分析

## 介面（框架固定）

- **目的**：把 G0 核准的範圍清單對到 code 位置，再切成模組；過程中發現 CR 本身不夠用時，在 P2 內整理 CR。範圍本身（做不做、留不留）在 P0 已經決定，P2 不重新討論。
- **層級**：專案
- **從哪裡進來**：
  - P1 完成之後。
  - C 變更處理判定「全新功能，不碰既有模組」→ 在 P2 追加模組。
- **輸入**：
  - 範圍清單（有 G0 核准）。
  - 來源快照（G0 核准的版本；不直接讀 Jira／Confluence）。
  - 基線報告。
  - 專案設定的 code 模組對照、共用層規則、衝突熱點，以及「CR 修訂寫回 Jira」。
- **輸出**：
  - 差異分析（`artifacts/delta.md`），至少包括：
    - 範圍清單裡標成新增、修改、移除的每一項一列：對到哪些 code、屬於哪個模組。
    - 每個模組的 code 範圍。
    - 受影響的既有功能（regression 範圍）。
    - 模組之間的相依與執行順序；改到衝突熱點檔案的模組標為序列。
  - CR 修訂紀錄（`artifacts/cr_revisions.md`，有修訂時才有）：每一項寫明類型（見下方 P2b）、對應的範圍清單項目、理由與 code 上的證據、P2b 的確認結果、有沒有寫回 Jira。
- **出口檢查**：範圍清單都有歸屬、CR 修訂都有歸屬、模組順序已定、regression 範圍已定。
- **出口關卡**：G1 範圍核准（一起核准差異分析與 CR 修訂紀錄）。
- **失敗退回**：見下方「資訊不足」。
- **迴圈上限**：待定。
- **可寫範圍**：可寫 `artifacts/delta.md`、`artifacts/cr_revisions.md`；不能改來源快照（寫回 Jira 與重抓快照由工具執行）；禁止改 FW source。
- **人怎麼參與**：P2a 不參與；P2b 與 AI 一起討論（有 CR 修訂提案時才進行）；G1 核准。
- **獨立性要求**：無。

### P2a 與 P2b

| 段落 | 誰做 | 做什麼 |
| :---- | :---- | :---- |
| P2a 分析 | AI，無人在旁 | 把範圍清單對到 code、切成模組；發現 CR 不夠用時，列出「CR 修訂提案」 |
| P2b CR 整理 | 人＋AI，互動式；有提案時才進行 | 一題一題確認修訂提案；「修改需求內容」要找 CR 負責人一起決定。確認後 P2a 用修訂後的內容接續 |

CR 修訂提案分四種：

| 類型 | 例子 | 本質 |
| :---- | :---- | :---- |
| 拆分 | 一張 CR 同時改到兩個模組（E39 的 2259 DICE UDS 同時改 `dice.c` 與 `lcp.c`） | 需求不變 |
| 補 CR | 範圍清單裡的項目沒有對應的 CR：P0 決定「移除」的既有功能、某張 CR 需要先做的前置修改 | 範圍不變 |
| 澄清 | CR 寫得不夠，判斷不出要改哪段 code | 需求不變 |
| 修改 | CR 和 code 現況矛盾，例如假設的機制在 code 裡不存在 | 需求內容改變 |

P2b 的界線：

- **會改到範圍清單標記的，P2b 不能決定**：例如真的是新功能，或某一項這版不做了 → 退回 P0，重開 G0（只審差異）。
- **行為細節的澄清留給 M1**：P2b 只處理卡住「對到 code、切模組」的問題。
- **CR 修訂紀錄是依據**：下游讀「來源快照＋CR 修訂紀錄」。專案設定允許寫回 Jira 時，由工具在人確認後寫回，再重抓來源快照，讓外部來源同步不會把它當成別人的修改；不允許時（例如有雙向隔離的 E39）只留在 GLADOS 內部。
- **只有 GLADOS 自己在 P2 提出的修訂在這裡處理**；其他人在 Jira 上的修改，一律由外部來源同步發現、走 C 變更分析（[framework/04 §4.6](../framework/04_rules.md#46-c-變更處理)）。

### 資訊不足

定義：**P2 有某個必要輸出填不出來，而且原因是某個輸入缺漏或有問題。** 缺的是哪個輸入，就退回產出那個輸入的地方（[framework/04 §4.5](../framework/04_rules.md#45-r-失敗分類) 的「輸入不足」）：

| 填不出來的輸出 | 缺的是 | 去哪裡 |
| :---- | :---- | :---- |
| 某一項對不到 code | 專案設定的 code 模組對照沒涵蓋 | 退回 P0 改專案設定，重開 G0（只審差異） |
| 某一項對不到 code | CR 內容不夠判斷 | P2b CR 整理 |
| 某一項做不到、兩項互相矛盾，或移除 A 但保留的 B 依賴 A | 範圍清單本身 | 退回 P0 改範圍清單，重開 G0（只審差異） |
| 需要 HW、SOC 等外部資訊才能判斷 | 外部資訊 | 登記待確認事項，節點轉為「等待外部回覆」 |
| regression 範圍定不出來 | 基線報告缺既有功能的測試結果 | 退回 P1 |
| 行為細節不清楚，但不影響對到哪段 code | **不算資訊不足** | 寫進交接清單的 `notes_for_next` 交給 M1，不擋 P2 |
