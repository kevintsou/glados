# P1 基線建立

## 介面（框架固定）

- **目的**：確認起點 code 能 build、能在驗證平台跑，建立對照基準。之後出現 FAIL 時，才分得出是新改動造成的，還是原本就壞。
- **層級**：專案
- **從哪裡進來**：
  - G0 核准之後。
  - C 變更處理判定「改基底、平台或 toolchain」，P0 重走之後（所有證據過期）。
  - P2 退回：基線缺既有功能的測試結果，regression 範圍定不出來。
- **輸入**：專案說明、範圍清單、專案設定（都已通過且有效，有 G0 核准）。範圍清單裡的既有功能（標成保留、修改、移除的項目）就是基線要跑的對象。
- **輸出**：基線報告（`artifacts/baseline/`）：
  - 每個 build 設定的結果、image hash、記憶體用量。
  - 既有功能的 golden log：綁定 image hash、測試集合與驗證環境的版本與 hash。
- **出口檢查**：build 零警告（所有 build 設定）、既有功能跑通、證據對應目前版本。
- **出口關卡**：無。
- **失敗退回**：環境或工具問題、起點本身 build 不過或跑不通 → 交給人（可能要回 P0 換起點）。
- **迴圈上限**：待定。
- **可寫範圍**：可寫 `artifacts/baseline/`；禁止改 FW source。
- **人怎麼參與**：不參與。
- **獨立性要求**：無。

**不同專案的起點**：delta 專案的起點是前代 code；新 IC 的起點是參考專案或骨架 code。不管哪一種，都要先有能跑的起點。
