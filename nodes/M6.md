# M6 獨立審查

## 介面（框架固定）

- **目的**：由獨立的審查者確認 diff 沒有功能錯誤、安全問題、記憶體越界、介面違約或違反必要規則。
- **層級**：模組
- **由誰做**：外部互動，由人開 agent 照審查 skill 完成；和 M4 是不同次開工、不同 session，最好換模型。交接說明記下 session 與模型，收件時核對（[framework/05 §5.5](../framework/05_checks.md#55-收件檢查)）。
- **從哪裡進來**：M5 PASS。
- **輸入**：模組 commit 與 diff、實作計畫（有的話）、模組 spec、驗收合約、架構文件、M5 驗證報告。
- **輸出**：審查報告與發現紀錄（`artifacts/modules/<模組>/review/`）；發現紀錄每一項一筆，格式見 [framework/03 §3.6](../framework/03_artifacts.md#36-紀錄)。
- **擋關檢查**：審查沒有未處置的阻擋項目。
- **出口關卡**：無。
- **失敗時**：有阻擋項目 → 回 M4 修正，計入 M4 的輪數；修正後重跑 M5、M6。需求或架構爭議 → 交給人。
- **可寫範圍**：可寫 `artifacts/modules/<模組>/review/`；禁止改 FW source 與測試。

放行規則見 [framework/04 §4.8](../framework/04_rules.md#48-審查放行)。審查結果綁定被審的 commit；diff 一改就要重新審查。

M6 沒有阻擋項目、M5 必要 case 全部 PASS、H 核准對應目前的 spec 與合約時，模組就算完成，由串接層直接判斷（v0.9 起不再有 M7）。
