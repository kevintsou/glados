# P5 全量驗收

## 介面（框架固定）

- **目的**：證明其他功能沒有被改壞，整版可以交付。
- **層級**：專案
- **從哪裡進來**：P4 完成之後。
- **輸入**：P4 的整合 branch 與 boot flow 報告、差異分析的 regression 範圍、所有模組的測試基準、範圍清單（判斷哪些 case 因為功能被移除而可以拿掉）。
- **輸出**：全量驗收報告（`artifacts/acceptance/`）：
  - regression 報告：綁定 image、測試集合與驗證環境的版本與 hash。
  - 靜態分析報告、授權掃描報告、安全審查報告。
- **出口檢查**：必要 case 全部 PASS、測試標準沒被放寬、靜態分析、授權掃描、安全審查、審查沒有未處置的阻擋項目、證據對應目前版本。
- **出口關卡**：G3 最終交付核准（綁定整合 branch 的 commit 與 image hash）。mask ROM 專案交付就是 tapeout，G3 的審查標準要比一般 release 更嚴。
- **失敗退回**：交給 R 失敗分類：先找出對應的模組，再依問題類型退回該模組的某一站。
- **迴圈上限**：待定。
- **可寫範圍**：可寫 `artifacts/acceptance/`；禁止改 FW source 與測試。
- **人怎麼參與**：只在關卡。
- **獨立性要求**：安全審查的執行者和各模組 M4 的執行者不同。
