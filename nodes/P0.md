# P0 專案啟動

## 介面（框架固定）

- **目的**：定這個專案的範圍與起點，讓後面每一站都有固定的依據。
- **層級**：專案
- **從哪裡進來**：
  - 新專案。
  - C 變更分析判定「改基底、平台或 toolchain」（project.md 要改版）。
- **輸入**（外部來源，P0 負責把版本固定下來）：
  - 範圍 CR 的來源：以 Jira Epic 為準，記錄讀取時間與 CR 清單快照。
  - 起點 repo 與 branch／commit。
  - 知識庫的版本。
  - 專案設定範本（[06](../framework/06_project_profile.md)）。
- **輸出**：
  - `project.md`：範圍 CR 來源與清單快照、T0、起點 commit、知識庫快照、禁止 agent 看到的 branch。
  - 專案設定：依 [06](../framework/06_project_profile.md) 的欄位填寫，不放機器路徑、密碼或 token。
- **出口檢查**：專案設定完整、起點版本可取得、知識庫版本已固定、隔離設定正確。
- **出口關卡**：G0 啟動核准（核准 project.md 與專案設定的版本）。
- **失敗退回**：資訊不足或起點不能用 → 留在 P0 補齊；仍無法解決 → 交給人。
- **迴圈上限**：待定。
- **可寫範圍**：可寫 `.glados/projects/<專案編號>/` 的 project.md 與專案設定；禁止改 FW source。
- **人怎麼參與**：與 AI 一起做（定範圍、T0、起點）。
- **獨立性要求**：無。

## 實作（待展開）

- **執行者**：人＋AI。
- **執行方式**：互動式 session。
- **工具**：Atlassian MCP（讀 Jira Epic、Confluence）、bootcode-qa。
- **待展開議題**：
  - **知識庫快照怎麼鎖住**（2026-10-07 討論）：bct_knowledge_base 的安裝程式會把 `Knowledge_Base/` 複製到全機共用的 `~/.claude/skills/bootcode-qa/database`。同一台機器上只要有人更新知識庫，執行中的專案看到的內容就跟著變。要真的鎖住快照，節點用的 skill 與知識庫路徑需要「每個專案一份」。
  - **隔離設定怎麼檢查**：工作區 repo 的 branch 清單可以自動核對；agent token 的權限範圍可能要人工確認。
