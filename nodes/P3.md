# P3 架構與介面

## 介面（框架固定）

- **目的**：定好模組的邊界，讓每個模組能各自往下走。
- **層級**：專案
- **從哪裡進來**：
  - G1 核准之後。
  - C 變更處理判定「改模組介面或記憶體預算」。
  - R 失敗分類判定「介面衝突」。
- **輸入**：差異分析與 CR 修訂紀錄（有 G1 核准；CR 修訂紀錄有修訂時才有）、基線報告、專案設定（記憶體預算、衝突熱點）。
- **輸出**：架構文件（`artifacts/arch.md`），至少包括：
  - 介面合約：每個模組的對外介面，用編號條目寫，讓 M3、M4 可以引用、過期時可以追蹤。
  - 記憶體預算分配。
  - 錯誤碼表。
  - boot flow 的變更。
- **出口檢查**：模組介面與預算已定。
- **出口關卡**：G2 架構審查。
- **失敗退回**：範圍有誤 → 退回 P2。
- **迴圈上限**：不設（架構審查會議有人在場）。
- **可寫範圍**：可寫 `artifacts/arch.md`；禁止改 FW source。
- **人怎麼參與**：與 AI 一起做（架構審查會議）。
- **獨立性要求**：無。

**改版時的影響**：依賴改動介面的模組從 M3 重走。
