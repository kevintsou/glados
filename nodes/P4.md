# P4 整合

## 介面（框架固定）

- **目的**：把所有模組合在一起，照 test plan 驗證整合後的行為（要跑哪些 flow、哪些後端介質，由 test plan 決定，GLADOS 不寫死）。bootcode 和 burner 在這裡第一次用彼此的完整版本一起驗；M5 時另一支程式用的是固定版本（[framework/09 §9.4](../framework/09_build_configurations.md#94-sandaruburner-是專案的一部分)）。
- **層級**：專案
- **由誰做**：工具步驟，由串接層執行（[framework/04 §4.2](../framework/04_rules.md#42-兩種執行方式)）。
- **從哪裡進來**：所有模組都完成（[framework/02 §2.3](../framework/02_workflow.md#23-模組流程)）。
- **輸入**：各模組的模組 commit、架構文件、test plan 的來源快照（[framework/09 §9.4](../framework/09_build_configurations.md#94-sandaruburner-是專案的一部分)）。
- **輸出**：
  - 整合 branch（commit SHA）。
  - boot flow 報告（`artifacts/integration/`）：綁定 image hash 與測試基準。
- **擋關檢查**：只寫在允許範圍內、build 零警告、記憶體在預算內、test plan 列的整合驗證項目全部 PASS、各模組驗收合約裡標「延到 P4」的 case 用完整版本全部 PASS（[framework/09 §9.4](../framework/09_build_configurations.md#94-sandaruburner-是專案的一部分)）。
- **出口關卡**：無。
- **失敗時**：交給人，先找出對應的模組，再決定回該模組的哪一站。
- **可寫範圍**：可寫整合 branch（只能合入已完成模組的 commit）、`artifacts/integration/`。

## 實作（待展開）

- **執行者**：工具負責合入、build、跑測試。需要判讀 log 時，由人開 agent 判讀。
- **工具**：openBCT。
- **待展開議題**：
  - 合入的順序與衝突處理方式。
  - image 載入與跑測試的串接方式，和 M5 是同一個問題（見 [M5](M5.md)）。
