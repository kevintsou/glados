# 人工關卡怎麼簽

> **這份文件回答**：人工關卡（G0–G3、GC、H1、H2、P7 的人確認）實際上怎麼操作。屬於實作，框架確認後才開始。
>
> **和框架的關係**：框架只規定關卡的規則（[framework/02 §2.4](../framework/02_workflow.md#24-人工關卡)）與核准紀錄的格式（[framework/03 §3.6](../framework/03_artifacts.md#36-核准與決定紀錄)）：關卡只做決定、最後一步由人親自完成、AI 不給核准建議、核准綁定身分與 hash。本文件記錄「用什麼做到」，工具改變時只改本文件。

---

## G1. 決策（2026-10-08）

- **不用 GitLab MR**。改由一個「簽核 skill」帶核准人走完審閱，最後由人親自送出決定。
- **最後的確認動作有兩個入口**：簽核指令跳出的系統對話框，以及 openBCT GLADOS 分頁的「核准」按鈕。兩個呼叫串接層服務的同一個 API；**先做對話框**，因為不開 openBCT 也能簽。
- **AI 不給「建議核准」**，改成讓核准人對每個關鍵風險逐項表態（反向 grill-me）。

---

## G2. 三個角色

| 角色 | 做什麼 | 不能做什麼 |
| :---- | :---- | :---- |
| 串接層 | 產生審查包；核對核准人與 hash；寫入核准紀錄 | — |
| 簽核 skill | 帶核准人審閱、逐項表態、整理決定內容 | 不能送出決定，也不能寫核准紀錄 |
| 簽核指令／GLADOS 分頁按鈕 | 讓人親自送出決定 | 不做判斷，只把人確認的內容送給串接層 |

**為什麼送出不能放在 skill 裡**：skill 是在 AI 的 session 裡跑的，skill 做得到的事，AI 也做得到。送出如果靠 skill 就能完成，無人在旁的節點（例如 M2）就可能核准自己的驗收合約，互動中的 AI 也可能把一句「ok」當成核准。

## G3. 流程

| 步驟 | 誰做 | 做什麼 |
| :---- | :---- | :---- |
| 1. 找出待簽 | skill | 向串接層查詢：哪些關卡在等這位核准人 |
| 2. 載入審查包 | 串接層產生，skill 呈現 | 見 G4 |
| 3. 引導審閱 | skill＋人 | 依這個關卡該核准什麼（[framework/02 §2.4](../framework/02_workflow.md#24-人工關卡) 的「核准什麼」欄），逐項帶過差異；人可以隨時發問 |
| 4. 逐項表態 | 人 | 對每個關鍵風險回答，例如「B4 有驗證缺口，這版接受嗎？」「這個延後處理的審查發現，接受延後嗎？」 |
| 5. 送出決定 | **人親自確認** | skill 整理決定內容（核准／退回／延後、核准範圍、逐項表態、備註），請核准人自己執行簽核指令；跳出的對話框顯示關卡、對象的編號、版本與 hash、決定內容，由人按下確認 |
| 6. 確認結果 | skill | 向串接層讀回核准紀錄，確認綁定的 hash 和審查包一致 |

「交給人」之後的決定（`kind: decision`）與 P7 的人確認（`kind: confirm`）也走同一套流程。

## G4. 審查包

由串接層用確定性程式產生，不是 AI 寫的；審查包本身有 hash，核准紀錄會記下它。

- 要核准的對象：編號、版本、內容 hash。
- 和上次核准之間的差異（重審只看差異）。
- 這一站的檢查結果摘要與證據連結。
- 還沒解決的項目：驗證缺口、待確認事項、延後處理的審查發現、自己做的檢查（`self_checks`）以外沒有證據的項目。
- 這次要逐項表態的風險清單（由規則從上面幾項產生）。

---

## G5. 守住的幾件事

- **身分**：送出決定時，用 Windows 登入帳號識別核准人。因為一定要有人實際按下確認，按下去的那個帳號就是核准人；串接層再核對他在專案設定這個關卡的核准人名單上。
- **節點的執行環境不裝簽核 skill**，也不允許執行簽核指令（節點專屬設定，見 [ai_node_execution.md](ai_node_execution.md)）。
- **審閱途中對象改版**：審查包作廢，skill 停下來，重新載入新的審查包。
- **AI 不給核准建議**：skill 只呈現事實與風險，讓人逐項表態；不寫「建議核准」「看起來沒問題」這類結論。

---

## G6. 建置路線步驟 2（還沒有串接層服務時）

- 簽核 skill 照樣帶流程。
- 審查包由簽核指令在本機產生（差異與 hash 都是確定性計算）。
- 核准人自己執行簽核指令、在對話框確認，指令產生核准紀錄檔；由扮演串接層的人提交到受保護的紀錄 branch。
