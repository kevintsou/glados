# BC-008 — 以前代 code base 衍生新 IC 的機械替換（含 ARM）

## 現況

bcgen 的生成是從公版骨架產生整個專案，以 Andes 為主，不認得 `duan` 架構，也沒有 ARM 的 scatter 生成。GLADOS v0.8.5 的 P1 要「以前代 code base 為底，依生成配方換成新 IC」：E39 是以 PS5037 的 code base 換上 PS5039 的 register、建立 PS5039 的 IC 目錄與 build 設定。bcgen 目前沒有這個模式。

## 本項範圍

bcgen 新增「衍生」模式，給 P1 的機械替換用：輸入是前代 code base 目錄、生成配方與外部來源快照（都由串接層傳入，BC-001），輸出只寫生成區與起始複製區。只做查表就能確定的替換；需要判斷的移植留給 P1 的 AI 移植步驟，不在本項。

register 快照、register 版本辨識與差異查詢、HW spec 查詢等外部來源工具，等第二批實作設計決定放在 bcgen 還是獨立工具，另開任務。

認領後補上實際 owned_paths、branch/worktree；先讀目標 repo 的 AGENTS.md 與最新 diff，不覆蓋其他 agent 的工作。

## 完成條件

- [ ] 依生成配方替換 register header：每個 block 採用配方指定的版本，依 block 與 code 目錄的對照放到正確位置。
- [ ] 建立新 IC 的目錄：以前代 IC 目錄為底原樣複製（不做字串替換，見 glados impl/recipe「名稱替換」），再依配方換 register；不修改生成區與起始複製區以外的檔案。
- [ ] ARM／DS-5：依配方的 build 設定對應，用固定規則複製新 IC 的 `.cproject` 設定（例如 `ps5037_*` → `ps5039_*`，改名稱、`_IC_NAME_`、IC 目錄路徑，產生新的唯一 ID，同步 `.settings/` 與 `.gitignore`）；scatter 原樣複製，記憶體差異交給 P1 移植。
- [ ] 機械替換後檢查 include 入口（配方的 `register_entry`）並列出差異清單：指到不存在的生成區檔案、生成區裡沒被 include 的檔案；不自行增刪 include。
- [ ] 共用層的 IC 旗標（例如 `duan` 的 `IC_NAME`）照配方加入新 IC。
- [ ] 配方缺項或對照不到時明確失敗並列出缺什麼，不自行推定；同樣輸入重跑結果逐檔相同（沿用 BC-007 的 manifest）。
- [ ] 輸入就是專案設定的配方區塊，照 [glados/impl/recipe.md](../../../impl/recipe.md) 的格式嚴格讀取：不認得或缺少的欄位直接失敗，不沿用 `normalize()` 丟欄位的行為；宣告支援的 `format` 版本。實作時把 recipe.md「還沒定的部分」定稿，必要時升 `format`，並在 GLADOS 補上 schema 檔。
- [ ] 用 E39 起點 `83dc1a65b` 加上 PS5039 register 快照實際跑一次，產出能交給 P1 的移植步驟；能不能 build 過不是本項的完成條件。
