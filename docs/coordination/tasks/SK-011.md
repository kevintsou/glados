# SK-011 — M2 測試實作 skill

## 現況

GLADOS v0.10（2026-10-20）起，串接層不派工給 AI：AI 的工作一律由人開 agent 照 skill 完成，串接層只開工與收件（[glados/framework/04_rules.md](../../../framework/04_rules.md) §4.2）。M2 的寫 case 原本由串接層派工給 AI，現在改由人開 agent 照本 skill 做；判別能力仍由串接層執行。

## 本項範圍

在 bct_knowledge_base 的 `Skills/` 新增 M2 寫 case 的 skill。用法和 bct-p0 一樣：人在工作區開 agent，叫它讀工作包、照本 skill 做。輸入是模組 spec、驗收合約、目前的 image 與既有的 openBCT case；產出是測試框架位置的測試實作與交接說明。

每個做 AI 工作的 skill 都要守 [glados/impl/ai_node_execution.md](../../../impl/ai_node_execution.md)「做 AI 工作的 skill 要守的規則」：先讀工作包；只寫可寫範圍；最多 3 輪（從工作包的輪數接著算，第 3 輪還沒過就停下來交給人）；寫交接說明後由 agent 或人提交；不碰簽核。

認領後補上實際 owned_paths、branch/worktree；先讀目標 repo 的 AGENTS.md 與最新 diff，不覆蓋其他 agent 的工作。

## 完成條件

- [ ] 驗收合約的每個必要情境都有對到的 case，交接說明列出對照表。
- [ ] 只寫測試框架位置；不改 FW source 與驗收合約。
- [ ] case 要真的檢查合約要求的行為，不能只用「印出訊息」當成功的證據（[glados/nodes/M2.md](../../../nodes/M2.md)）；判別能力由串接層在提交後執行，交接說明寫明預期哪些 case 在目前的 image 上會 FAIL。
- [ ] 優先沿用 openBCT 既有的 case 與測試框架，對不上的列為缺口。
- [ ] 封裝照既有 skills：自帶 references、`agents/openai.yaml`、evals（含 fixture）。在 Claude Code 與 Codex 都能用，用法照 bct-p0 的「執行平台」一節。檔案用 LF，加進 `Skills/.gitattributes`。
- [ ] 契約參考固定的 GLADOS commit（v0.10 之後）與對應的節點卡；不自己發明框架沒有的欄位或規則。
- [ ] 用合成的工作包與工作區至少實跑一次 evals，回報結果；不碰真的專案 repo。
