# SK-009 — 審查 skill（M2 測試審查、M6、P1 移植審查）

## 現況

GLADOS v0.10（2026-10-20）起，串接層不派工給 AI：AI 的工作一律由人開 agent 照 skill 完成，串接層只開工與收件（[glados/framework/04_rules.md](../../../framework/04_rules.md) §4.2）。M2 的測試審查、M6 獨立審查、P1 的移植審查原本由串接層派工給另一個 AI session，現在改由人另開一次開工、照本 skill 審查。

## 本項範圍

在 bct_knowledge_base 的 `Skills/` 新增 一個共用的審查 skill，依工作包的節點切換審查重點。用法和 bct-p0 一樣：人在工作區開 agent，叫它讀工作包、照本 skill 做。輸入是被審的 diff、被審那次的交接說明與節點卡指定的依據（M2：驗收合約；M6：spec、合約與必要規則；P1：建立設定、移植說明與 register 差異）；產出是 `artifacts/.../review/` 的審查報告與交接說明，不改 code。

每個做 AI 工作的 skill 都要守 [glados/impl/ai_node_execution.md](../../../impl/ai_node_execution.md)「做 AI 工作的 skill 要守的規則」：先讀工作包；只寫可寫範圍；寫交接說明後由 agent 或人提交；不碰簽核。

認領後補上實際 owned_paths、branch/worktree；先讀目標 repo 的 AGENTS.md 與最新 diff，不覆蓋其他 agent 的工作。

## 完成條件

- [ ] 每項發現寫成 `glados.finding/v2` 的內容（位置、類型、影響、處置），`blocking` 照類型決定（[glados/framework/04_rules.md](../../../framework/04_rules.md) §4.8），審查的 AI 不能自己改。
- [ ] 交接說明記下自己的 session 編號與模型，以及被審那次的執行編號；被審那次的 session 和自己相同時，停下來不審。
- [ ] 三種審查各有重點清單：M2 是 case 有沒有真的落實合約；M6 是功能錯誤、安全、記憶體越界、介面違約、必要規則；P1 是每處移植有沒有依據、有沒有超出移植範圍或碰到生成區。
- [ ] 先評估能不能以 corvia_code_review 為基礎，或在本 skill 裡呼叫它；評估結果寫進交接紀錄。
- [ ] 封裝照既有 skills：自帶 references、`agents/openai.yaml`、evals（含 fixture）。在 Claude Code 與 Codex 都能用，用法照 bct-p0 的「執行平台」一節。檔案用 LF，加進 `Skills/.gitattributes`。
- [ ] 契約參考固定的 GLADOS commit（v0.10 之後）與對應的節點卡；不自己發明框架沒有的欄位或規則。
- [ ] 用合成的工作包與工作區至少實跑一次 evals，回報結果；不碰真的專案 repo。
