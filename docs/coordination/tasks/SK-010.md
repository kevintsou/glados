# SK-010 — P1 移植 skill

## 現況

GLADOS v0.10（2026-10-20）起，串接層不派工給 AI：AI 的工作一律由人開 agent 照 skill 完成，串接層只開工與收件（[glados/framework/04_rules.md](../../../framework/04_rules.md) §4.2）。P1 的移植原本由串接層派工給 AI，現在改由人開 agent 照本 skill 做；機械替換與 build 仍由串接層執行。

## 本項範圍

在 bct_knowledge_base 的 `Skills/` 新增 P1 第 3 步的移植 skill。用法和 bct-p0 一樣：人在工作區開 agent，叫它讀工作包、照本 skill 做。輸入是機械替換 commit、include 差異清單、建立設定的 `port_paths` 與理由、紀錄 branch 上的 register 快照與 HW spec 快照、上一輪的交接說明；產出是移植範圍內的修改、`artifacts/base/` 的移植說明與交接說明。

每個做 AI 工作的 skill 都要守 [glados/impl/ai_node_execution.md](../../../impl/ai_node_execution.md)「做 AI 工作的 skill 要守的規則」：先讀工作包；只寫可寫範圍；最多 3 輪（從工作包的輪數接著算，第 3 輪還沒過就停下來交給人）；寫交接說明後由 agent 或人提交；不碰簽核。

認領後補上實際 owned_paths、branch/worktree；先讀目標 repo 的 AGENTS.md 與最新 diff，不覆蓋其他 agent 的工作。

## 完成條件

- [x] 只改 `port_paths` 列的範圍，不碰生成區；需要改範圍以外的檔案時，不自己擴大，交給人（通常是回 P0 補建立設定）。
- [x] 每處修改在移植說明寫明依據：建立設定的項目、register 差異（可用 BC-009 的 register 差異工具）或 HW spec 的出處。
- [x] include 差異清單的每一項都有處置（加 include、改名、說明為什麼不用）。
- [x] 和機械替換的 commit 分開 commit；session 裡自己 build 的結果只供參考。
- [x] 循環最多 3 輪，從工作包的輪數接著算（含移植審查有阻擋項目退回的累計）。
- [x] 封裝照既有 skills：自帶 references、`agents/openai.yaml`、evals（含 fixture）。在 Claude Code 與 Codex 都能用，用法照 bct-p0 的「執行平台」一節。檔案用 LF，加進 `Skills/.gitattributes`。
- [x] 契約參考固定的 GLADOS commit（v0.10 之後）與對應的節點卡；不自己發明框架沒有的欄位或規則。
- [x] 用合成的工作包與工作區至少實跑一次 evals，回報結果；不碰真的專案 repo。
