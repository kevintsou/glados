# BC-010 — DS-5 headless build 的機器可讀包裝

## 現況

這些地方都要「build 所有必要設定，而且零警告」，而且要留下能核對的證據（image hash、warning 清單）：

- P1 的起點檢查與量基線（第 1、5 步，共用待辦 OBC-012、OBC-013）。
- M4 實作的擋關檢查「build 零警告」。
- 「影響 build 的環境改變就重新 build」這條自動規則。

bct_knowledge_base 的 `ds5-build` skill 已經寫好了怎麼用 DS-5 的 `eclipsec` headless build、有哪些已知的雷、log 要怎麼判讀，但它是給 agent 照著做的說明，不是串接層能直接呼叫、會回傳機器可讀結果的工具。skill 由 EdwinLuo 維護，照知識庫「報不改」的規矩，發現 skill 有問題要寫 report 交給維護者，不能直接改。

這台機器裝有 DS-5 v5.28.1 與 v5.29.3。

## 本項範圍

在 bct_knowledge_base 的 `tools/` 下新增一個命令列工具：照 `ds5-build` skill 記載的做法執行 headless build，把結果寫成 JSON。

- 只做 ARM DS-5；Andes 線不在本項。
- 不燒錄、不碰晶片，那是 remote-ice 的事。
- 不修改 `Skills/ds5-build/`。

認領後補上實際 owned_paths、branch/worktree；先讀目標 repo 的 AGENTS.md 與最新 diff，不覆蓋其他 agent 的工作。

## 完成條件

- [x] **命令列**：
  - 輸入：`ws_fw` 目錄（固定 commit 的工作區）、要 build 的設定清單（從 `.cproject` 讀，不寫死）、輸出目錄。
  - 每個設定輸出一筆 JSON：
    - 結果：成功、失敗或環境錯誤。
    - error 與 warning 的數量與清單：檔案、行號、訊息與代碼。
    - 產出檔（`.axf`、`.bin`）是否存在，以及 sha256。
    - 有 map 檔時記記憶體用量。
    - log 位置與耗時。
- [x] **判讀**：
  - 成功與否看產出檔與 log，不只看 exit code。
  - skill Step 3 的已知雷都要處理：從哪個 shell 發起、clean 階段的「Build Finished」被誤當完成、沒有平行 build 的路徑等。
  - 雜訊清單照 skill 與 references：真的 compiler warning 不能被當成雜訊濾掉。
- [x] **環境**：
  - DS-5 版本、`eclipsec`、license 都自動偵測，不寫死。
  - 偵測不到或授權失敗時，回報「環境錯誤」，不回報成 build FAIL。
- [x] **不動 source**：不修改被 build 的 source；Eclipse workspace 與 metadata 放暫存目錄；同時只跑一個 build。
- [x] **E39 實跑一次**：
  - 用起點 `83dc1a65b` 的 6 個設定在本機實際跑一次，回報每個設定的結果。
  - build 不過不算本項失敗，只要結果判讀正確，而且和人工看 log 的結論一致。
- [x] **測試**：只用 Python 標準函式庫。log 判讀用 fixture 測試，涵蓋：
  - 成功。
  - 有 warning。
  - compile error。
  - link error。
  - 授權失敗。
  - clean-only 的假完成。
  - 產出檔缺少。
- [x] **回報 skill 的問題**：發現 skill 有錯或缺漏，照 `reports/traps/_TEMPLATE.md` 寫 report，不改 skill。
