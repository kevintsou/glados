# OBC-028 — GitLab 唯讀查詢模式（觀察者不 clone 看進度）

## 現況

GLADOS 分頁只能選本機 FW Git repo，用本機 git 讀取；專案狀態存在本機 SQLite，服務只綁 127.0.0.1。只想看進度的管理者必須自己 clone、pull，或連到執行者的機器，才看得到狀態。P0 草稿匯出後不自動 commit／push，推上 GitLab 前別人看不到。

OBC-004 的完成條件已有「查進度不必 clone／連設備」，但沒有規定讀取來源是 GitLab API，也沒有觀察者角色；本項補上這兩件事。

## 本項範圍

openBCT GLADOS 分頁的 GitLab 唯讀查詢模式，依 glados impl/service.md I4「觀察者只看進度」。

- 讀取來源抽成介面：本機 git 與 GitLab API 兩種實作；狀態推導（OBC-004）不依賴讀取來源。
- 用 GitLab API 列出 `glados/records/*` branch 找出專案，固定讀同一個 commit 的 `.glados/projects/<專案編號>/`；工作 branch 的產出也各自固定 commit。
- 觀察者模式不啟動服務、不派工、不提供執行／重跑／核准。
- 隔離專案的 token 只限只含允許 branch 的獨立工作區 repo。

不含：遠端看即時狀態、狀態摘要頁、主動通知（impl/service.md I8 #7、#8 待決）。

認領後補上實際 owned_paths、branch/worktree；先讀目標 repo 的 AGENTS.md 與最新 diff，不覆蓋其他 agent 的工作。

## 完成條件

- [ ] 只給 GitLab 專案網址與唯讀 token（例如 `read_api`），不 clone、不需本機 repo，就能列出專案並顯示流程圖與節點狀態。
- [ ] 同一份紀錄，以本機 git 與 GitLab API 讀取時推導出的節點狀態相同（有測試覆蓋）。
- [ ] 畫面標示讀取的 commit 與時間；即時狀態連不到時標示「無法取得」，不推定已停止。
- [ ] 觀察者模式下執行、重跑、核准的操作停用，直接呼叫 API 也被拒絕。
- [ ] token 不寫入 repo 或共用設定；只存在本機設定或憑證管理。
