# OBC-029 — 串接層統一 commit 與 push 工作 branch 及紀錄 branch

## 現況

P0 草稿存在本機 SQLite；「匯出草稿」只寫進 worktree，不 commit、不 push。推上 GitLab 前，觀察者（OBC-028）看不到任何進度。OBC-002 管正式紀錄的受保護 writer、OBC-014 管待同步恢復，但都沒有涵蓋工作 branch 的 push、push 順序、commit 訊息欄位與送審／分享草稿。

## 本項範圍

依 glados framework/03 §3.12 與 impl/service.md I6.2：

- 節點只在執行工作區 commit，回收後由串接層 push 工作 branch；節點使用的 token 不需要 push 權限。
- 先 push 工作 branch、確認成功後才寫入並 push 紀錄 branch。
- 固定時間點 commit：節點回收、放行、抓來源快照與版本同步報告、送審；GUI 儲存草稿不 commit。另提供「分享草稿」。
- commit 訊息帶 `GLADOS-Project`、`GLADOS-Node`、`GLADOS-Run`、`GLADOS-Input`。
- push 被拒絕時 fetch 後交給 S 版本同步；網路或權限失敗標「待同步」並重試。不 force push。

認領後補上實際 owned_paths、branch/worktree；先讀目標 repo 的 AGENTS.md 與最新 diff，不覆蓋其他 agent 的工作。

## 完成條件

- [ ] 節點回收後工作 branch 由服務 push；紀錄 branch 只在工作 branch push 成功後才寫入（有測試覆蓋：工作 branch push 失敗時紀錄 branch 不前進）。
- [ ] 儲存草稿不產生 commit；送審與分享草稿才 push，分享的 commit 標示為草稿。
- [ ] commit 訊息帶規定欄位；S 版本同步能據此區分串接層 commit 與人工 commit。
- [ ] 遠端有新 commit 時不 force push、不自動 rebase；網路失敗標「待同步」，服務重啟後能接續。
- [ ] CI 排除規則（OBC-023）未生效、或 push 目標不符合隔離設定時，拒絕打開自動 push。
