# BC-011 — remote-ice 機器可讀包裝（載入 image 與讀回驗證）

## 現況

C2（上機測試）決定由串接層在同一次工具步驟裡，依序做「載入 image」與「跑 openBCT 測試」。要證明測試時跑的是哪個 image，先用 ICE 在載入後讀回記憶體、比對 hash（[glados/notes/c2_lab_design.md](../../../notes/c2_lab_design.md) 第 1、2 項）。

bct_knowledge_base 的 `remote-ice` skill 已經能遠端操作 lab 機的 ICE 與 UART：

- 工具組在 `Skills/remote-ice/toolkit/`，包括 `Connect-Ice.ps1`、`Ice.psm1`、`backend/Ds5.psm1`、`backend/AndesGdb.psm1`、`scripts/Invoke-IceCapture.ps1`、`scripts/load_and_capture.ps1`、`transport/`。
- 傳輸方式可以是 ssh，也可以走 watcher。
- 支援多台 bench。

但這套工具是給 agent 照說明操作的，串接層沒辦法直接呼叫並拿到機器可讀的結果。

skill 由 EdwinLuo 維護，照知識庫「報不改」的規矩：發現 skill 有問題要寫 report，不能直接改。已知的雷有一份 report：`reports/traps/261019_remote-ice_save-icememory-pulls-stale-same-name-dump.md`，`Save-IceMemory` 可能拉回同名的舊 dump。讀回驗證必須避開這個問題。

## 本項範圍

在 bct_knowledge_base 的 `tools/` 下新增一個命令列工具，呼叫 remote-ice 的工具組完成以下事情，並把結果寫成 JSON：

1. 把指定的 image 載入指定的 bench。
2. 用 ICE 讀回指定的記憶體範圍，和 image 裡對應的內容比對 hash。
3. 可以選擇 free run 並收開機那段的 UART log。

不包括的事：

- 跑 openBCT 的測試：由 openBCT 負責。
- 設備認領與排隊：之後接公司的 FPGA Queue，細節還沒定（c2_lab_design 第 4、8 項）。
- 修改 `Skills/remote-ice/`。

可以用的 bench 清單使用者還在整理（c2_lab_design 第 3 項），本項的測試與開發一律用**假的 bench 與假的傳輸**；真機 smoke 要等 bench 清單。

認領後補上實際 owned_paths、branch/worktree；先讀目標 repo 的 AGENTS.md 與最新 diff，不覆蓋其他 agent 的工作。

## 完成條件

- [ ] **命令列**：
  - 輸入：bench 代號（對應到一份 bench 設定，放本機設定，不進 repo）、image（`.axf` 或 `.bin`）、要讀回驗證的記憶體範圍（位址與長度；可以給多段）、輸出目錄，以及是否 free run 收 UART、收多久。
  - 輸出：一份 JSON，內容包括：
    - 載入的結果：成功、失敗或環境錯誤。
    - image 的 sha256。
    - 每一段讀回的位址、長度、讀回內容的 sha256、image 對應內容的 sha256、是否相符。
    - UART log 的位置與 sha256。
    - 實際用到的 toolkit 版本、傳輸方式、bench 代號、耗時。
- [ ] **讀回驗證**：
  - image 對應內容的算法要寫清楚，例如 `.bin` 依載入位址取對應的那一段，`.axf` 依 load region 取。
  - 每次 dump 都用不重複的檔名，並核對 dump 的大小與時間，避開「拉回同名舊 dump」的雷。
  - 讀回不相符時記 FAIL；讀不到記環境錯誤。兩者都不能算成功。
- [ ] **環境錯誤和失敗要分開**：連不上 lab 機、ICE 沒反應、傳輸逾時、授權問題都是「環境錯誤」；載入後讀回不符是「失敗」。退出碼分開定義，例如 0 成功、1 失敗、2 環境錯誤。
- [ ] **不改 remote-ice**：只透過它的工具組呼叫，不修改 `Skills/remote-ice/`。如果工具組沒有提供機器可讀的介面，就在本工具裡解析它的輸出，並在 README 寫明依賴哪些輸出格式。發現 skill 有問題，照 `reports/traps/_TEMPLATE.md` 寫 report。
- [ ] **假的 bench 與傳輸**：
  - 提供一個假的模式：用本機目錄模擬 lab 機，用檔案模擬 ICE 記憶體與 UART。
  - 測試要涵蓋：
    - 載入成功且讀回相符。
    - 讀回不符。
    - 拉回舊 dump，要被抓出來。
    - 連不上，記環境錯誤。
    - ICE 逾時。
    - UART 收集。
    - 多段讀回。
- [ ] **證據**：bench 設定裡的 IP、帳號這類資訊不寫進 JSON 的公開欄位；只記 bench 代號，詳細資料放在證據目錄的內部檔案。
- [ ] **只用 Python 標準函式庫**。PowerShell 工具組由本工具以子程序呼叫。
