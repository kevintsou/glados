# OBC-030 — 以確定性 checker 核對起點 build 設定的必要／排除處置

## 現況

2026-10-19 使用者決定 P0 不經 bcgen 盤點（[glados/impl/bcgen.md](../../../impl/bcgen.md) B1、B4），原本由 bcgen `check_build_targets`（BC-004）負責的「每個 target 都已處置」核對沒有人接手。P0a 的 AI（bct-p0）會自己讀 `.cproject` 列出 target，但那是節點自查，只供參考（[glados/framework/05_checks.md](../../../framework/05_checks.md) §5.1）。openBCT 目前沒有這個 checker。

## 本項範圍

openBCT 串接層裡一個不靠 AI 的 checker：從固定起點列舉 build 設定，和專案設定的處置比對，產出可保存的檢查報告。P0 出口（「專案設定完整」）與 P1 開始時用同一個。不依賴 bcgen；可參考 bct_knowledge_base `fedcbdb` 起 bcgen 讀 DS-5 `.cproject` 的方式（BC-004 現況）。

認領後補上實際 owned_paths、branch/worktree；先讀目標 repo 的 AGENTS.md 與最新 diff，不覆蓋其他 agent 的工作。

## 完成條件

- [ ] 從串接層準備的固定起點（commit 對應的 worktree 或 git blob）列舉 build 設定：ARM 讀 `ws_fw/.cproject` 的 configuration，Andes 讀對應的 build 設定；每項附來源檔、hash 與讀法。格式不支援或讀不完整時明確報「無法完整盤點」，不當成清單已完整。
- [ ] 和專案設定的「build 設定」處置比對，分別報出：漏列、仍待確認、排除沒有理由或範圍依據、列為必要但起點不存在。任一項存在就不算 PASS；核准且有理由的排除不算遺漏，也不計 PASS。
- [ ] P0 出口與 P1 開始時用同一個 checker 與同一套規則；P1 開始時比對對象是 G0 核准的版本，不一致走「輸入不足」由 R 退回 P0。
